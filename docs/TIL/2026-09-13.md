## 개발을 다시 시작하며

Python과 Django로 외부 3D 생성 API를 연결했던 경험을 바탕으로, 이번에는 Windows 게임 영어 도우미를 만들기 시작했다. 과거 미라벨 프로젝트는 별도의 포트폴리오 프로젝트이며 이번 앱의 기반 코드는 아니다.

이번 목표는 직접 만들며 배우고, 이후 배포와 상업적 운영까지 이어가는 것이다. 오늘은 전체 기능 대신 작은 창과 버튼부터 만들었다.

## 오늘 직접 해본 것

1. Codex가 생성한 Windows 앱을 실행하고 버튼을 눌러 영어와 한글 발음이 나타나는 것을 확인했다.
2. Cursor에서 `MainWindow.xaml`의 영어 표시 영역 `FontSize`를 `24`에서 `30`으로 바꿨다.
3. 저장하고 다시 빌드한 앱에서 글자가 커진 것을 확인했다.
4. `MainWindow.xaml.cs`에서 버튼 클릭 시 표시할 문장을 바꿨다.
5. 다시 실행한 앱에서 아래 결과를 확인했다.

```text
I'll come with you.
아일 컴 위드 유
```

초기 프로젝트 생성, SDK 설치, 빌드와 실행은 Codex가 수행했다. 글자 크기와 문장 수정, 저장, 화면 확인은 내가 직접 했다.

## 오늘 접한 용어

| 용어 | 읽는 법·뜻 | 이번 작업에서의 역할 |
| --- | --- | --- |
| C# | 씨샵. 이름 자체가 언어 이름이다. | 버튼 클릭 후 동작을 작성하는 언어 |

오늘 만든 고정 문장 표시 창은 첫 실습 결과다. 명세의 MVP 1단계인 ‘한국어 음성 → 영어 + 한글 발음’은 아직 완성하지 않았다.

## XAML: 화면의 모양을 정하기

```xml
<Window Title="게임 영어 도우미" Width="620">
```

- `Window`: 창을 뜻하는 요소(태그).
- `Title`, `Width`: 제목과 너비를 설정하는 속성. 함수가 아니다.
- 따옴표 안의 내용: 속성에 넣는 값.

Django에서 보았던 HTML처럼 화면 구조를 표현한다는 점이 비슷하다. 다만 이번 파일은 웹 HTML이 아니라 Windows 앱용 XAML이다. 속성을 여러 줄로 나누는 것은 주로 읽기 편하게 하기 위한 것이며, Python처럼 들여쓰기로 실행 블록을 정하지 않는다.

`xmlns`는 XML namespace의 줄임말로, `Window`, `Button` 같은 이름을 어떤 의미로 해석할지 지정한다. 주소처럼 보이는 문자열은 이름을 구분하기 위한 식별자이며, 실행할 때 그 주소에서 버튼을 내려받는다는 뜻은 아니다. 지금은 기본 선언을 외우기보다 역할만 알아두기로 했다.

- `x:Name="EnglishText"`: C#에서 찾을 수 있도록 화면 요소에 이름을 붙인다.
- `x:Class`: 화면과 연결할 C# 클래스를 지정한다.

직접 바꾼 `FontSize="30"`은 영어 표시 영역 전체에 적용됐다. 따라서 클릭 전 안내 문구도 커지고, 클릭 후 영어 문장도 같은 크기로 표시됐다.

## C#: 클릭했을 때 내용을 바꾸기

```csharp
EnglishText.Text = "I'll come with you.";
PronunciationText.Text = "아일 컴 위드 유";
```

첫 줄은 ‘EnglishText라는 화면 요소의 Text 속성에 오른쪽 문자열을 넣는다’는 뜻이다.

- `.Text`: 표시할 글자 내용.
- `=`: 오른쪽 값을 왼쪽에 넣는 대입.
- `"..."`: 문자열을 나타내는 큰따옴표.
- `;`: 명령 끝 표시.

이 코드는 `ShowExample_Click`이라는 함수 안에 있다. XAML의 `Click="ShowExample_Click"`이 버튼 클릭과 이 함수를 연결한다. C#에서 클래스 안의 이런 함수는 메서드라고도 부른다.

```text
앱 실행 → 창 구성 → 버튼 클릭 → ShowExample_Click 실행 → 두 Text 속성 변경
```

## 편집·저장·실행을 구분하기

이번 환경에서는 사이드바에서 파일을 확인하고, 실제 수정은 기존에 쓰던 Cursor로 했다. Codex가 처음에 사이드바에서 바로 수정할 수 있다고 안내해 혼동이 있었고, Cursor로 열어 해결했다.

Cursor 파일 탭의 흰색 점은 저장 전 상태를 나타냈다. Ctrl + S로 저장한 뒤 점이 사라지는 것을 확인했다.

```text
Cursor에서 코드 수정 → 저장 → 실행 중인 게임 영어 도우미 종료 → 빌드 → 실행 → 확인
```

Cursor는 계속 열어둬도 된다. 다시 빌드하기 전에 닫는 대상은 우리가 만든 ‘게임 영어 도우미’다. 실제로 이전 앱 프로세스가 남아 실행 파일 교체를 막았던 일이 있었고, 해당 프로세스를 종료한 뒤 빌드가 성공했다.
