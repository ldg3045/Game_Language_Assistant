# 2026-09-16 TIL — 부분 성공, 테스트 분리와 MVP 범위

> 4일 차 실제 작업과 대화를 바탕으로 Codex가 작성한 복습 초안이다. 사용자가 나중에 자신의 표현으로 수정할 문서이며 개념 숙달을 가정하지 않는다.

## 오늘 한 일

Codex는 발음 생성에 실패해도 영어 번역은 유지하도록 코드를 수정하고 자동 검사와 고정 텍스트 비교를 수행했다. 나는 앱에서 A/B 거점, 5탄, 연막 문장을 직접 말하고 결과 화면을 공유했다. 이후 마이크 없이 명확한 텍스트를 붙여 넣어 번역만 비교했다.

## 전체 실패와 부분 성공

기존 구조는 영어 번역과 한글 발음이 둘 다 성공해야 표시했다. 발음만 잘못돼도 영어까지 보이지 않았다.

```text
영어 단계 실패 → 영어 번역 실패 안내
영어 성공 → 발음 성공 → 영어와 발음 표시
영어 성공 → 발음 실패 → 영어 유지 + 발음 실패 이유
```

이것이 Partial success(파셜 석세스, 일부 단계의 성공)다. 라이브러리를 교체한 것이 아니라 결과 전달과 오류 처리 방식을 바꾼 것이다. 현재는 발음 요청까지 끝난 뒤 표시하며 영어를 먼저 실시간 표시하지 않는다. 번역하기를 다시 누르면 두 단계 모두 재시도한다.

취소하거나 원문을 바꾼 뒤에는 이전 요청의 영어도 표시하면 안 된다. ‘일부 결과를 보존한다’는 규칙보다 ‘현재 원문에 해당하는 결과만 보여 준다’는 규칙을 함께 지키는 것이 중요하다.

## 음성 인식과 번역을 분리해서 시험하기

마이크 시험은 음성 인식 → 번역 → 발음의 전체 흐름을 확인한다. 텍스트를 직접 붙여 넣는 시험은 음성 인식을 건너뛰므로 뒤의 오류를 Whisper 탓으로 볼 수 없다.

이번에는 A/B를 직접 입력해도 영어에서 누락됐다. 5.56mm 탄약이라고 풀어 써도 ‘다 떨어졌다’를 ‘얼마 남지 않았다’로 번역했다. 따라서 게임 은어와 음성 인식만의 문제가 아니라 번역 모델의 기본 의미 보존 문제도 있다.

| 평가 기준 | 이번 사례 |
| --- | --- |
| 식별자 보존 | A/B가 영어에도 남는가 |
| 수치·종류 보존 | 5.56mm가 탄환 5발로 바뀌지 않는가 |
| 상태 보존 | out of ammo(탄약 소진)와 running low(탄약 부족)를 구분하는가 |
| 행동·방향 보존 | 연막탄 사용과 왼쪽 우회를 함께 전달하는가 |
| 불필요한 추가 금지 | 원문에 없는 for a moment(잠깐)를 넣지 않는가 |

번역기의 문장과 글자 단위로 같아야 하는 것은 아니다. 자연스러운 표현 차이는 허용하되 중요한 정보가 달라지면 오류다.

## 형식 검사와 언어 품질은 다르다

한글 발음에 허용하지 않는 문자가 있거나 생성이 끝나지 않으면 프로그램이 실패로 처리한다. 반대로 한글만으로 된 틀린 발음은 통과할 수 있다. 영어가 표시된다는 사실도 의미가 정확하다는 보장은 아니다.

오늘 사용자 화면에서는 발음 실패 후 영어가 유지됨을 확인했다. 이는 오류 처리 검증의 성공이다. 발음 정확도가 해결된 것이 아니며 실제 잘못된 원시 발음 응답은 화면만으로 알 수 없다.

## 테스트 용어

- Local(로컬): 내 PC에서 처리한다는 뜻이다. 게임을 켰는지와는 무관하다.
- 앱 단독 테스트: 게임 없이 앱에서 마이크 입력과 출력 결과를 확인한다.
- 실사용 모사 테스트: 준비한 문장이나 음성으로 실제 상황과 비슷하게 시험한다.
- 인게임 실전 테스트: 실제 게임에서 상대방 음성·대화를 대상으로 시험한다. 이 프로젝트에서는 MVP 이후 진행한다.
- A/B 테스트: 같은 조건에서 두 모델이나 설정을 비교하는 시험이다. 상대 음성을 녹음해 시험하는 것 자체가 A/B 테스트는 아니다.
- Troubleshooting(트러블슈팅): 증상, 원인, 해결 시도, 검증, 남은 한계를 구분해 기록하는 문제 해결 과정이다.

## 가중치, 프롬프트, 용어집

| 용어 | 의미 | 오늘 상태 |
| --- | --- | --- |
| 모델 가중치 | 학습으로 얻은 모델 내부 수치 | 변경하지 않음 |
| Fine-tuning(파인튜닝) | 기존 모델의 가중치를 추가 학습으로 조정 | 하지 않음 |
| Prompt(프롬프트) | 요청할 때 모델에 전달하는 지시문 | 기존 지시문 유지 |
| 용어집 | 특정 표현의 뜻을 참고 자료로 제공 | 새로 적용하지 않음 |

프롬프트 수정은 추가 학습이 아니다. 그러나 특정 문장에만 맞춰 계속 수정하면 개발 범위가 커지고 다른 문장에서 성능이 나빠질 수도 있다. ‘5탄’ 같은 은어는 고난도 평가 자료로 남기고, 모든 사례를 지금 해결하려 하지 않는다. 현재 모델은 최종 확정이 아니라 후보이며, 기본 의미 보존을 제한적으로 평가한 뒤 MVP 흐름을 이어간다.

## 보고를 정정할 때

실제 발화는 ‘너 5탄 있어?’였고 최초 보고의 ‘있니’는 내가 적은 오타였다. 이 부분을 음성 인식 오류로 계산하면 안 된다. 화면에 추가된 ‘혹시’는 별도 차이다. 후속 직접 입력 시험에 적힌 ‘너 탄약 있니?’는 또 다른 입력이다.

텍스트를 붙여 넣은 뒤 남은 ‘인식 완료 0.9초’는 이전 음성 인식 상태다. 이번 텍스트 입력의 처리 시간으로 해석하면 안 된다. 수동 수정 상태 표시와 발음 단계 오류 문구 개선은 아직 미구현이다.

## 다음에 확인할 것

- 식별자·숫자·소진 상태·행동·방향 보존을 고정 문장으로 제한적으로 비교한다.
- 자동 검사 통과, 사용자가 확인한 화면, 모델의 언어 품질을 구분한다.
- 앱 단독 시험은 계속하고 인게임 실전 검증은 MVP 이후 진행한다.
- 특정 게임 전용 최적화나 추가 학습으로 현재 MVP 범위를 확대하지 않는다.

오늘 로컬 코드 변경은 별도 문서 게시 커밋에 포함하지 않는다. 개발 일지는 수행 사실을 기록하므로 원격 저장소의 코드가 아직 이 구현과 같다는 뜻은 아니다.
