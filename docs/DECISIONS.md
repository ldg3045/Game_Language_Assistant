# 기술 결정 기록

## 2026-09-16 — 부분 성공과 MVP 범위 유지

- 발음 단계 실패가 성공한 영어까지 가리지 않도록 부분 성공 결과를 사용한다. 영어 즉시 표시나 발음만 재시도는 추가하지 않고 기존 두 단계 요청을 유지한다.
- 특정 게임 은어에 맞춰 모델 가중치를 변경하거나 추가 학습하지 않는다. 모델·프롬프트·용어집은 오늘 변경하지 않았다. 명확한 입력에서도 나타나는 식별자 누락과 소진/부족 변경은 기본 의미 보존 문제로 평가한다.
- 게임별 용어집·고유명사 최적화는 후속 범위다. 현재 사례에만 맞추는 반복 수정으로 MVP를 확대하지 않고, 제한된 비교 후 후보 모델의 한계를 기록한다.
- 앱 단독 마이크 시험·실사용 모사 시험은 개발 중 계속한다. 실제 게임 상대방 음성·대화를 사용하는 실전 검증은 MVP 이후 진행한다.

## 2026-09-15 — 모델은 후보 유지, 발음 생성과 형식 검증 구분

- 사용자 요청에 따라 qwen3:4b를 최종 모델로 확정하지 않는다. 현재 기본 실행값인 qwen3:8b도 연결·품질 비교를 위한 임시 MVP 후보다. 향후 다른 로컬 모델과 외부 API를 비교한 뒤 결정한다.
- ITranslationService가 화면과 공급자 구현의 교체 경계다. OllamaTranslationService는 생성자에서 모델 이름을 받도록 보완해 로컬 후보 교체 시 내부 요청·화면 코드를 수정할 필요가 없게 했다. 선택 UI나 자동 대체 기능은 추가하지 않았다.
- 현재 발음은 영어 번역 결과를 같은 LLM에 별도로 보내 한글 발음을 직접 생성한다. 프로그램은 JSON·길이·허용 문자 등을 검사하고 실패 처리한다. 발음 사전·IPA·음소 변환이나 잘못된 한글 발음을 자동 교정하는 후처리는 없다.
- 추후 발음의 일관성을 개선할 때 영어 텍스트 → 발음 결과를 담당하는 별도 모듈로 분리하는 것을 권장한다. 현재는 평가와 경계 설계만 기록하며 별도 발음 엔진은 구현하지 않는다. 사전·음소 기반 방식도 고유명사·숫자·억양 등의 예외 검증이 필요하다.

## 2026-09-15 — 로컬 번역의 최소 교체 경계

- 사용자 요청에 따라 번역도 로컬로 시작한다. `ITranslationService`와 `TranslationResult` 하나로 화면과 모델 실행을 분리했다. 별도 DI 프레임워크, 플러그인 선택 화면, 서버·계정·결제는 도입하지 않았다.
- 원문 확인 후 ‘번역하기’로 영어·한글 발음을 함께 생성한다. 직접 수정한 현재 원문을 사용하며 원문이 바뀌면 이전 번역과 진행 중 응답을 무효화한다.
- 로컬 구현은 Ollama의 고정 루프백 주소를 사용한다. HTTP를 사용하지만 외부 유료 API는 아니며 음성 대신 텍스트만 PC 내부에 전달한다. 리다이렉트와 프록시를 사용하지 않는다.
- 첫 후보 Qwen3 4B는 발음 품질이 부족해 8B로 변경했다. 모델을 바꾸기 위해 화면 코드를 변경할 필요는 없었다. 추론 모드는 더 느리고 발음 개선이 충분하지 않아 사용하지 않는다.
- 한 번에 영어·발음을 생성하는 방식 대신 같은 모델에 영어 번역 → 확정된 영어의 한글 발음을 순서대로 요청한다. 서비스 내부 두 호출이며 화면과 결과 규약은 그대로 유지한다. 일부 단어 발음 오류가 남아 품질 완료로 간주하지 않는다.
- 단일 발화만 처리하며 이전 대화 문맥은 아직 없다. JSON 응답 검증, 입력 2000자 제한, 응답 120초 제한, 중복 실행 방지와 취소를 포함한다.

## 2026-09-15 — 로컬 Whisper와 수정 가능한 한국어 원문

- 사용자가 첫 엔진으로 로컬 Whisper를 선택했다. Whisper.net/Whisper.net.Runtime 1.9.1과 다국어 base 모델을 연결했다. 모델 파일은 별도 다운로드·SHA-256 검증 후 사용하며 Git에서 제외한다.
- 첫 구현은 CPU 최대 4스레드로 실행한다. GPU 설정과 대형 모델은 추가하지 않았다. base의 한국어 품질이나 게임 중 속도가 충분하다고 판단한 것은 아니며 실제 발화로 평가할 기준점이다.
- 녹음 종료 후 원문을 한 번 표시하고 선택적으로 수정한다. 임시 실시간 문장·대화 기록·번역은 제외한다.
- ISpeechRecognizer에 인식 호출을 분리하고 로컬 구현 안에서 16kHz 모노 변환과 모델 실행을 처리한다.
- 원문·음성은 저장·전송하지 않는다. 인식 작업은 UI의 녹음과 별도 복사본을 소유하며 종료 시 정리한다. 지우기와 창 닫기는 취소를 요청하고 이전 결과를 화면에 재적용하지 않는다.
- 모델 준비는 개발용 스크립트로 명시적으로 실행한다. 앱 내부 다운로드 UX와 배포 설치 과정은 후속 범위다.
- 실제 실행 중 취소 검사에서 네이티브 종료가 발생해, 인식 계산은 완료를 기다린 뒤 취소된 결과를 버리는 방식으로 제한했다. 즉시 중단을 보장하지 않으며 UI에서 취소 중 상태를 안내한다.

## 2026-09-14 — 음성 인식 엔진 교체 경계

- 다음 단계는 녹음 종료 후 인식으로 시작한다. 녹음·화면·후속 번역과 음성 인식 구현을 분리하고, 공통 인터페이스로 로컬/API 구현을 교체할 수 있게 한다.
- 지금 두 엔진을 모두 구현하거나 실시간 처리 구조를 미리 만들지는 않는다. 현재는 방향 합의이며 관련 코드는 아직 없다.
- 첫 엔진은 미선정이다. 클라우드 API, Windows AI Speech Recognition, whisper.net의 환경 조건·정확도·지연·게임 자원 영향을 확인한 뒤 선택한다.
- Live Captions 자막창을 읽는 우회 방식은 제품 기반으로 채택하지 않았다. 자체 인식 API 사용과 기존 자막창에서 텍스트를 가져오는 것은 별개다.
- 로컬 음성 인식과 번역·발음 생성의 실행 위치는 각각 결정할 수 있다. 유료 API 연동은 별도 비용을 확인한 뒤 진행한다.

## 2026-09-14 — 메모리 음성 수집으로 확장

앞선 ‘음량 계산 후 버리기’에서 최신 입력 구간을 메모리에 보관하는 방식으로 확장했다. 디스크 저장과 외부 전송은 하지 않는다. 종료 시 장치의 원래 형식으로 WAV 데이터를 생성하며, 실제 STT 요구 형식 변환은 공급자 선택 후 구현한다.

입력 한도는 초기 운영값으로 60초/원시 데이터 16 MiB를 사용한다. 원시 데이터 제한 외에 WAV 생성 과정에서 복사 메모리도 일시 사용한다. 콜백에서 수집 용량을 제한하고 UI 타이머로 경과 시간도 제한한다. 자동 종료와 사용자 종료는 같은 정리 경로를 사용한다.

## 2026-09-14 — 버튼 기반 마이크 입력

- 시작·종료 버튼과 장치 선택, 음량 표시를 먼저 구현한다. 게임 음소거 연동, 전역 단축키, VAD는 후속 범위다.
- NAudio.Wasapi 2.2.1과 해당 버전의 WasapiCapture API를 사용한다. 직접 COM 연동을 구현하는 부담을 줄이고 필요한 WASAPI 모듈만 참조한다. 최신 버전이라는 의미는 아니며, 구현·검증한 API 버전으로 고정했다.
- 장치 기본 믹스 형식과 공유 모드를 사용한다. 현재 PCM 16/24/32비트와 IEEE float 32비트 음량 계산을 지원하고 그 외 형식은 오류로 안내한다.
- 오디오 입력은 MicrophoneInput에 분리하고, UI는 50ms 간격으로 최대 음량을 읽는다. 오디오 패킷마다 UI 작업을 쌓지 않는다.
- 이 초기 단계에서는 음성을 측정 후 버렸다. 같은 날 위의 ‘메모리 음성 수집으로 확장’ 결정으로 변경했다. 파일 저장, 외부 API 전송, STT는 아직 구현하지 않는다.
- 사용자 요청에 따라 학습용 추가 실습 대신 실제 개발을 우선한다. 상세 협업 지침은 루트 AGENTS.md를 따른다.

## 2026-09-13 — 첫 Windows 앱의 기술과 범위

**선택:** C# + .NET 10 + WPF.

Python/PySide6, TypeScript/Electron과 비교했다. Windows 전용 오버레이와 오디오 기능으로 확장할 때 C# 중심으로 유지보수 범위를 묶을 수 있다는 판단으로 선택했다. 실제 성능이나 특정 FPS 호환성을 검증해서 내린 결론은 아니다.

사용자는 Python/Django 학습 경험이 있어 C#/XAML을 새로 배워야 한다. 이를 고려해 기초 강의를 길게 선행하기보다 작은 기능을 만들고 직접 수정하는 방식으로 진행한다.

**첫 구현 범위:** 일반 창, 예시 표시 버튼, 영어·한글 발음 텍스트. 화면과 동작의 연결을 배우기 위해 간단한 코드 비하인드 방식을 사용했다. 별도 구조용 라이브러리는 추가하지 않았다.

**후속 검토:** NAudio/WASAPI, STT 공급자, 영어·발음 생성 방식. 아직 라이브러리 버전이나 API 공급자를 확정하지 않았다. 게임 호환성 및 설치 배포 방식도 후속 단계에서 검증한다.
