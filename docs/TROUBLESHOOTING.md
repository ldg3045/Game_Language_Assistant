# 문제 해결 기록

## 2026-09-16 — 발음 실패로 성공한 영어까지 표시되지 않음

- **증상:** 영어와 발음을 모두 성공해야 표시하는 구조 때문에 발음 단계만 실패해도 영어가 보이지 않고 실패 단계가 불명확했다.
- **원인:** 번역 결과를 영어·발음 한 쌍의 성공 또는 전체 예외로 처리했다. 특정 사용자 사례에서 어떤 발음 문자가 오류를 일으켰는지는 당시 응답이 없어 미확정이다.
- **해결:** TranslationResult에 선택적 발음과 발음 오류를 추가했다. 영어는 검증 후 유지하고, 발음 단계의 형식·연결·시간 초과 오류를 부분 성공으로 반환한다. 화면은 영어 번역 실패와 발음 생성 실패를 구분한다.
- **선택 이유:** 라이브러리나 모델 교체 없이 결과 처리 경계를 개선했다. 영어 즉시 표시나 발음만 재시도는 이번 범위에 넣지 않았으며 기존 번역하기로 두 단계를 재시도한다.
- **검증:** 자동 검사에서 빈 값·혼합 문자·길이·응답 형식·잘린 응답·연결·시간 초과 오류와 영어 유지, 원문 수정·취소·종료 후 결과 폐기를 확인했다. 빌드 경고·오류는 0개였다.
- **한계:** 발음 자체의 정확도를 개선한 것은 아니다. 실제 모델 품질과 사용자 마이크 시험은 별도로 확인한다.

## 2026-09-15 — 작은 번역 모델의 발음 출력 오류

- **문제:** Qwen3 4B는 시험 문장의 영어 번역은 생성했지만 발음을 로마자, 다른 문자 또는 부정확한 한글로 생성했다.
- **시도:** 한글 출력 지시와 JSON Schema의 문자 범위 제약을 추가했다. 실제 응답에는 여전히 데바나가리·키릴 문자가 섞여 있어 스키마만 믿을 수 없었다.
- **대응:** 응답을 받은 뒤에도 한글 음절과 허용 구두점만 있는지 검사한다. 잘못된 출력은 번역 성공으로 표시하지 않는다. 동일한 코드 구조에서 8B 모델로 바꿔 품질을 비교한다.
- **한계:** 한글 문자 검사는 정확한 발음을 보장하지 않는다. 발음 사전이나 음소 기반 처리는 후속 비교 대상으로 남긴다.
- **추가 시험:** 8B 추론 모드는 시험 문장당 약 4~10초였으나 발음 오류가 남았다. 영어 번역과 발음을 분리한 최종 구성은 ‘부족하다 → 완전히 없다’의 의미 강화와 일부 부정문 발음을 개선했다. 다른 단어의 발음 오류는 해결되지 않았으며 화면에 한계를 표시했다.

## 2026-09-15 — Whisper 실행 중 취소 시 네이티브 엔진 종료

- **문제:** 실제 모델 실행 중 CancellationToken 취소 검사에서 `GGML_ASSERT(ne0 == ne01) failed`가 발생하고 테스트 프로세스가 종료됐다.
- **대응:** Whisper.net 1.9.1의 네이티브 계산에는 취소 토큰을 전달하지 않는다. 변환 전후에는 취소를 확인하고, 시작된 모델 계산은 끝까지 기다린 뒤 취소 결과를 폐기한다. 계산 중 결과 열거도 중간에 끊지 않는다.
- **검증:** 기존 검사, 실행 중 취소, 취소 후 재인식, 모델 누락 검사가 모두 통과했다. 상위 라이브러리의 내부 근본 원인까지 규명한 것은 아니다.
- **제약:** 취소 버튼이 계산을 즉시 멈추지는 않는다. 취소 완료 전에는 새 인식을 시작하지 않아 작업이 겹치지 않게 한다. 장기적으로 런타임 갱신 또는 별도 프로세스 실행을 검토할 수 있다.

## 2026-09-15 — 확장 WAV의 샘플 변환 실패

- **문제:** Whisper 입력용 오디오 변환 검사에서 `Unsupported source encoding`이 발생했다.
- **원인:** WaveFileReader가 확장 WAV를 WaveFormatExtensible 대신 WaveFormatExtraData로 읽어, 기존 형식 정규화가 적용되지 않았다.
- **해결:** 확장 헤더의 하위 형식 GUID를 확인해 PCM 또는 32비트 실수 형식으로 정규화한 뒤 모노·16kHz 변환을 수행했다.
- **검증:** PCM 16/24/32비트, 실수 및 확장 WAV 변환, 길이·진폭·취소 검사가 통과했다. 실제 base 모델에 합성 신호를 넣는 실행 검사도 통과했다.
- **한계:** 합성 신호 검사는 모델 실행 가능 여부를 확인하며 한국어 발화 정확도를 입증하지 않는다.

## 2026-09-14 — 오디오 패키지 복원 실패

- **문제:** 마이크 기능에 필요한 NuGet 패키지를 내려받는 단계가 실패했다.
- **원인:** 당시 제한된 실행 환경의 네트워크 접근 문제였다.
- **해결:** 승인된 권한으로 패키지 복원을 수행한 뒤 빌드했다.
- **확인:** NAudio.Wasapi 2.2.1을 사용하는 앱 빌드가 완료됐다.
- **주의:** 소스코드 오류와 패키지를 내려받지 못하는 환경 문제를 구분한다. 모든 복원 실패가 같은 원인이라는 뜻은 아니다.

## 2026-09-14 — WAV 검증에서 프레임 정렬 오류

- **문제:** 수집한 WAV를 확인하는 테스트에서 1바이트 읽기가 오디오 블록 정렬 제약에 걸렸다.
- **원인:** 오디오 리더가 요구하는 한 프레임 크기를 고려하지 않은 테스트 코드였다.
- **해결:** 한 프레임 크기의 버퍼를 읽도록 검사 코드를 수정했다.
- **확인:** WAV 구조·길이, 입력 데이터 복사, 시간·용량 제한 검사가 통과했다.
- **배운 점:** 오디오의 한 프레임은 같은 시점의 모든 채널 샘플을 포함한다. 임의의 바이트 단위 읽기가 항상 허용되지는 않는다. 이 문제는 실제 녹음 손상이 확인된 사례가 아니라 검사 방법의 문제였다.

## 2026-09-13 — SDK 부재 및 첫 빌드 권한

- **문제:** C# 프로젝트를 빌드할 개발 도구가 없음.
- **증상:** `dotnet --info`에서 `No SDKs were found.` 표시.
- **원인:** 런타임만 설치된 상태.
- **시도한 방법:** 설치 상태 확인 후 .NET 10 SDK 설치. 첫 빌드에서 사용자 폴더 `.dotnet` 접근 거부 발생.
- **해결:** 승인된 설치와 권한 확장을 통해 최초 설정 및 빌드 완료.
- **배운 점:** 실행 환경과 개발 도구는 다르며, 이번 최초 설정은 작업 폴더 외부 접근을 필요로 했다.

## 2026-09-13 — 실행 파일 교체 실패

- **문제:** 글자 크기 변경 후 재빌드 실패.
- **증상:** `MSB3026` 경고와 다른 프로세스가 실행 파일을 사용 중이라는 메시지.
- **원인:** 해당 프로젝트의 이전 실행 프로세스가 남아 있었음. 창이 보이지 않았던 구체적인 이유는 확인하지 않음.
- **시도한 방법:** 프로세스 ID와 실행 경로 확인.
- **해결:** 해당 실습 앱 프로세스만 종료한 뒤 재빌드. 경고·오류 0개로 성공.
- **배운 점:** Cursor는 열어두어도 되지만 빌드할 앱의 기존 실행은 종료해야 파일 교체 문제를 피할 수 있다.

## 2026-09-13 — 코드 편집 위치 혼동

- **문제:** 사이드바에 열린 파일에서 직접 수정하지 못함.
- **증상:** 사용자가 글자를 편집할 수 없다고 보고.
- **원인:** Codex가 해당 화면의 편집 가능 여부를 확인하지 않고 수정·저장을 안내했음.
- **시도한 방법:** 열기 메뉴를 통해 기존 Cursor 코드 편집기로 파일을 열었음.
- **해결:** Cursor에서 수정하고 Ctrl + S로 저장한 뒤 앱을 빌드·실행.
- **배운 점:** 파일 미리보기, 코드 편집기, 실행 프로그램의 역할을 구분해서 안내해야 한다. 이 기록은 당시 사용한 화면에 대한 것으로 모든 앱 버전의 편집 지원 여부를 단정하지 않는다.
